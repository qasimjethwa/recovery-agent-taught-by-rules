# recovery-copilot-toolcalls

Tool-calling tasks for failed-payment recovery, generated by a
deterministic rule engine — Qasim Jethwa's shipped
[Recovery Copilot](https://github.com/qasimjethwa/Failed-payment-recovery)
— for the **Lexsi AI Safety & Alignment Hackathon, Track 3 (Agentic
Fine-tuning)**.

Every gold label is correct **by construction**: the engine classifies a
payment failure and prescribes the exact recovery action, channel, delay
and message, so the task generator and the audit harness share the same
ground truth.

## Files

| File | What it is |
|---|---|
| `train.jsonl` | 400 training cases (50 per failure reason) |
| `eval.jsonl` | 128 held-out eval cases (disjoint transaction IDs, 0 overlap) |
| `evaluate.py` | The AuditKIT-style scorer: exact-match accuracy, argument accuracy, invalid-call rate, end-to-end task success (overall + per failure reason) |
| `eval_job.py` | The HF Jobs evaluation runner (base vs. LoRA-tuned) |
| `train_job.py` | The HF Jobs LoRA SFT runner |
| `config.yaml` | Training configuration |

## Task format

Each row: a failed-payment scenario (`instruction`, `scenario`), the 4
available tools (`schedule_retry`, `send_customer_message`,
`offer_alternate_method`, `silent_retry` with JSON schemas), the gold
call sequence (`expected_calls`, 1–3 calls), and the expected recovery
decision. The 8 failure reasons: insufficient funds, OTP timeout, bank
server error, card declined, network drop, incorrect CVV, expired card,
daily limit exceeded.

The eval split holds 243 gold tool calls and 757 gold argument values,
including 8 edge cases where UPI is the original method and the
bank-error silence rule (no customer contact — silent backend retry) is
exercised.

## How it was used

- **AgentTune step:** LoRA SFT of CohereLabs/aya-expanse-8b on
  `train.jsonl` → adapter
  [qasimjethwa/aya-expanse-8b-recovery-lora](https://huggingface.co/qasimjethwa/aya-expanse-8b-recovery-lora)
- **AuditKIT step:** base vs. tuned models scored on `eval.jsonl` with
  `evaluate.py` — before/after metrics in the model card and the HF
  Article write-up.

## Limits

Synthetic single-domain distribution; message text comes from a template
bank; the engine's per-rule `successRate` values are configured
assumptions for the original demo's simulation, never measured results.
